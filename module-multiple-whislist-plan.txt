================================================================================
ARCHITECTURE DECISION
================================================================================

The core Magento_Wishlist has a UNIQUE constraint on customer_id (one wishlist
per customer). We do NOT touch the core module. We build a fully standalone
module with our own tables, and intercept the core "Add to Wishlist" button
via a Plugin.


================================================================================
DATABASE SCHEMA (3 new tables)
================================================================================

TABLE: magic_wishlist
  - wishlist_id     int PK (auto-increment)
  - customer_id     int FK → customer_entity
  - wishlist_name   varchar(255)
  - is_default      tinyint  (1 = default list)
  - shared          smallint (0/1 sharing flag)
  - sharing_code    varchar(32) (encrypted share token)
  - created_at      timestamp
  - updated_at      timestamp

TABLE: magic_wishlist_item
  - item_id         int PK (auto-increment)
  - wishlist_id     int FK → magic_wishlist
  - product_id      int FK → catalog_product_entity
  - store_id        smallint FK → store
  - qty             decimal(12,4)
  - comment         text (user note on product)
  - added_at        timestamp

TABLE: magic_wishlist_price_alert
  - alert_id        int PK (auto-increment)
  - customer_id     int FK → customer_entity
  - product_id      int FK → catalog_product_entity
  - wishlist_id     int FK → magic_wishlist
  - price_at_add    decimal(12,4) (price when item was added)
  - last_sent_at    timestamp (last alert email sent)
  - is_active       tinyint (1 = alert enabled)

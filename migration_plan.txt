RECOMMENDATION: APPROACH 2 — Fresh 2.4.8 + Selective Module Migration
------------------------------------------------------------------------

Approach 1 (direct upgrade) is off the table because:
- 40+ vendor namespaces, 130+ modules in app/code — many are competing
  implementations of the same feature (e.g., two blog modules: Magefan +
  Mageplaza, two store pickup modules: Helios + Magespacex)
- Swissup Argento + Codazon theme suite — completely irrelevant in a
  PWA/headless setup. These 15+ modules become dead weight and fight the upgrade
- Manadev LayeredNavigation suite (16 modules) — built for LUMA/Argento theme,
  needs full re-evaluation for GraphQL
- Upgrading 130 modules across 6 version jumps simultaneously is extremely
  high-risk, and most of what you'd carry over you don't even need

The fresh 2.4.8 + uat_helios DB setup is the correct foundation.

PHASE 4: GRAPHQL LAYER (PWA-specific work)
================================================================================

For every module that exposes data the PWA frontend needs:
  1. Check if the module already has etc/schema.graphqls + resolver
  2. If not, write the GraphQL schema + resolver
  3. Test via GraphQL Playground at http://magic.local/graphql

Modules that will definitely need GraphQL resolvers:
  - Helios/Checkout (custom shipping/delivery options)
  - Helios/PriceRender / Helios/PriceDecimal (custom pricing display)
  - Pincode/CheckDelivery (pincode availability check)
  - Helios/NotifyMe (back-in-stock)
  - Helios/Tracking / Helios/Trackorder
  - Helios/Storepickup
  - Helios/Wishlist (if extending default)


================================================================================
PHASE 5: PER-MODULE MIGRATION PROCESS (Repeat for each module)
================================================================================

For each module being ported:

  Step 1: Copy module
    From: /var/www/html/htdocs/uat-helios/app/code/Namespace/Module
    To:   /var/www/html/magic/app/code/Namespace/Module

  Step 2: Update registration.php if needed

  Step 3: Check etc/module.xml dependencies
    - Ensure all declared dependencies exist in 2.4.8

  Step 4: Review PHP code for deprecated 2.4.2 patterns:
    - Direct ObjectManager usage
    - Deprecated API calls (check Magento 2.4.8 upgrade guide)
    - Constructor injection changes
    - Any removed interfaces or classes

  Step 5: Remove frontend-only files (PWA replaces this UI)
    - view/frontend/layout/
    - view/frontend/templates/
    - view/frontend/web/js/  (unless backend JS is needed)

  Step 6: Run php bin/magento setup:upgrade
  Step 7: Run php bin/magento setup:di:compile
  Step 8: Verify no errors before moving to the next module


================================================================================
PHASE 6: PWA FRONTEND WIRING
================================================================================

As each backend module is migrated and its GraphQL layer is ready:
  1. Add corresponding PWA component override in /var/www/html/magic/pwa/
     (using the overrides pattern: overrides/@magento/venia-ui/lib/components/)
  2. Wire up the GraphQL query/mutation in the PWA component
  3. Test end-to-end: PWA → GraphQL → Magento module → DB
